# 驿路通商 · 动态经济沙盘

古代驿路经营游戏的动态经济系统。城镇有产出与消耗,千支 NPC 商队在路网间套利,
价格随库存与流量动态调整;任何"低买高卖"的差价都会被指数库存曲线、关税运费和
NPC 套利在数个回合内吃掉。配套经济监控、地图、驿站、商队四个界面,模拟在
Web Worker 线程内运行。

## 快速开始

```bash
npm install
npm run dev          # 启动界面(http://localhost:5173)

npm run bench        # 性能基准:30 城镇 × 1000 商队的单日结算耗时
npm run test:invariants  # 经济不变量(白银恒等式/库存边界/活跃度/自愈)
npm run test:alerts      # 报警阈值链路
npm run smoke        # 无头浏览器冒烟测试(需 Edge,自动起 CDP)
npm run build        # 类型检查 + 生产构建
```

## 动态定价如何吃掉倒卖利润

每城镇每商品的价格只由**库存相对目标库存的偏离**决定:

```
unitPrice(stock) = basePrice × exp( k × (target − stock) / target )
```

- 库存被买走 → 价格指数上涨;大量砸盘 → 价格指数下跌
- 大单按曲线**积分**成交,天然带滑点:买得越多均价越贵,卖得越多均价越低
- 一笔跨城镇套利同时在两端压价:买贵卖贱,价差在几轮内收敛到运费带宽

叠加两道固定成本形成**无套利带宽**:

- 关税 2%,买卖双向,税收退出流通(白银回收)
- 运费 = 重量 × 里程 × 费率,计入商队持仓成本

1000 支 NPC 商队持续扫描邻接路线,只在扣除运费后净利 > 2% 时出手,
把任何超出带宽的价差主动搬平。`npm run bench` 末尾的"倒卖自愈验证"可看到:
首轮有利润,第二轮利润归零,第三轮转亏,套利窗口关闭。

## 实体经济与白银循环

- 城镇按画像(粮产区/牧场/织工坊/商埠)每日产出或消耗四类商品
- 库存超出仓容(目标 ×2.2)的产出浪费;缺货累计缺货天数并推高价格
- 驿站养马,每日吃草料;公文酬劳是白银**投放**,关税/运费/养护是**回收**
- 城镇银库低于兜底线时由官银补充
- 白银恒等式逐日对账:`Δ流通总量 ≡ 投放 − 回收`(测试中闭合到浮点精度 1e-15)

## 报警规则

每个游戏日结算时,按商号汇总当日贸易净利。对任一商号,用**其余商号的均值**
(排除自身,避免异常值抬高基准)判定:

```
单日利润 ≥ 30 万文  且  单日利润 > 同业均值 × 10   → 报警
```

绝对门槛防止低基数误报。报警记录当日每段买卖的起讫城镇、商品、数量与利润,
在监控页点击报警卡片即可在地图上用红色虚线还原整条路线。

## 性能

- Tick 复杂度 O(商队数),NPC 仅在到达城镇时做邻居 × 4 商品的 O(1) 比价
- 每日供需结算 O(城镇 × 商品),与商队数量无关
- 实测(见 `npm run bench`):30 城镇 × 1000 商队,完整游戏日(8 子步)
  平均约 2ms、P95 < 3ms,红线 50ms 余量充足
- 模拟运行在 `sim.worker.ts`,主线程仅按 10fps 接收快照渲染,结算不卡界面

## 目录结构

```
src/core/
  constants.ts   商品定义、税率/运费/报警阈值等经济规则
  types.ts       城镇、道路、商队、报警、白银账本类型
  rng.ts         确定性随机数(种子可复现)
  worldgen.ts    程序生成 30 城镇、道路网、千支商队
  market.ts      指数定价、积分报价、滑点、关税运费、成交执行
  engine.ts      时间推进、NPC 套利 AI、玩家交易、日结、报警、刷钱复现
  protocol.ts    Worker 消息协议与界面快照
src/worker/
  sim.worker.ts  Worker 线程:定时推进、结算计时、消息处理
src/ui/          四个页面与交易面板(原生 TS + SVG,无框架)
bench/           性能基准、不变量、报警、无头浏览器测试
```

## 设计取舍

- **无框架 UI**:界面是定时快照驱动的只读视图,原生 DOM 模板 + SVG 足够,
  避免引入运行时;状态单一来源在 Worker 内的引擎
- **玩家只有一支商队**:报警口径需要把玩家与 8 个 NPC 大商号放在同一统计层级;
  多支商队可在 `worldgen.ts` 调整 owner 分配
- **结算计时只算 CPU**:`settleMs` 累计 8 个子步的纯计算时间,不含子步间的
  调度等待,与 Node 基准口径一致
